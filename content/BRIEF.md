# 執筆ブリーフ（共通）

あなたは応用情報技術者試験（AP）科目A（旧午前・四肢択一・80問/150分）対策コンテンツの執筆者です。
2026年11月7日に受験する社会人向けに、スマホで縦スクロールして学ぶ「ドゥームスクロール学習アプリ」の教材を書きます。
作業ディレクトリ: D:\development\playground\ap  。スキーマは content/SCHEMA.md を必ず最初に読むこと。

## 品質基準
- 対象レベル: 応用情報 科目A。基本情報より一段深い。頻出論点・定番のひっかけ・計算問題を網羅する。
- 「網羅」が最優先。担当中分類の全小分類について、IPAシラバス（試験要綱・シラバス Ver.7相当）に載る主要用語・概念を漏れなくカバーする。POCではない。
- concept（解説カード）: 1枚1論点。body は「結論→理由→例」の順で 2〜5文、スマホで15秒で読める長さ（100〜260字）。points は 2〜4個、各30字以内。tip は「試験ではこう問われる／これと混同しやすい／語呂合わせ」など実戦的に。
- terms（用語カード）: 一問一答で即答できる短い定義（60字以内目安）。concept と重複してよいが def は言い換える。
- questions（四肢択一）: 本試験と同じ文体（「〜はどれか。」「適切なものはどれか。」「〜を求めよ。」）。選択肢は4つとも同じ粒度・同じ文体で、紛らわしい誤答を作る。計算問題は途中式を explanation に書き、必ず検算する。`answer` の位置は 0〜3 を均等にばらす（連続で同じ位置にしない）。difficulty 1:2:3 ≈ 3:5:2 の比率。
- tf（○×）: 典型的な誤解・ひっかけを突く命題。○と×を半々に。
- 過去問の丸写しは禁止（著作権）。ただし過去問で繰り返し問われている論点を狙うのは大歓迎。
- 正確さ最優先。自信のない数値・年号・条文は書かない。
- 文体: 解説は「です・ます」調で簡潔に。問題文は本試験調（常体）。英略語には初出で日本語名を添える（例: 「DMZ（非武装地帯）」）。
- HTMLは使わない。改行は \n。数式は Unicode で（×, ÷, ², √, ≒, →）。表が必要なら「A: 1, B: 2」のように箇条で。

## 手順
1. content/SCHEMA.md を読む。
2. 担当する各中分類について `content/<slug>.concepts.json` と `content/<slug>.questions.json` を書く。長い場合はファイルを一度に書かず、Bashのヒアドキュメントや追記で分割して作成してよい。ただし最終的に各slugにつきこの2ファイルのみ。
3. `node tools/validate.mjs content` を実行し、自分の担当ファイルの ERROR を0にする。warn も可能な限り直す（特に answer distribution skewed）。
4. 他人のファイル、tools/、アプリ本体には触らない。
5. 完了報告: 各slugの件数（c/t/q/x）とvalidate結果を簡潔に。
